# App Flow Document

## Onboarding and Sign-In/Sign-Up

When a new user arrives at the application, they first see a clean landing page that briefly explains the Komik Tracker and offers two clear buttons: one to create an account and another to sign in. Clicking the create account button takes the user to a full-screen registration form that asks for a username, email, and password. Password strength feedback appears as they type, and form validation immediately points out any missing or malformed information. Once the registration form is correctly filled and submitted, the application calls the backend’s `/api/auth/register` endpoint. The server hashes the password with bcrypt, creates a user record in the database, and returns a JWT stored in an HttpOnly cookie. The user is then redirected to the main dashboard.

If an existing user clicks the sign-in button instead, they land on the login page where they provide their email and password. Any failed login attempts due to wrong credentials trigger an inline error message. On a successful login request to `/api/auth/login`, a new JWT cookie is set and the user is sent to the dashboard. At any point, the user can click a “Forgot Password” link on the login page, which leads them to a page where they enter their email. Submitting this form triggers a call to `/api/auth/forgot`, sending a password reset email via the Resend service. The email contains a one-time link that leads to a reset page where the user enters a new password and confirmation. The reset form submits to `/api/auth/reset` with the token, and on success it displays a confirmation message and offers a link back to the login page.

Signing out is always available in the header drop-down menu. Clicking “Sign Out” calls the `/api/auth/logout` endpoint to clear the HttpOnly cookie and then redirects the user back to the landing page. If a user forgets their password or tries to access a protected route without a valid token, the middleware redirects them automatically to the login page, preserving the originally requested path so they can resume their work after signing in.

## Main Dashboard or Home Page

Upon successful login, the application presents the dashboard as the user’s landing zone. The page is split into a collapsible sidebar on the left, a site header across the top, and the main content area in the center. The sidebar contains links labeled Dashboard, Comics, Master Data, Recycle Bin, Activity Log, and Settings. The header shows the user’s avatar, name, and a drop-down menu for sign out and theme toggling. In the main content area, the top section displays two chart widgets—one Pie chart showing the distribution of comic genres and one Bar chart illustrating reading progress. Below these, KPI cards summarize total comics, unread items, and recently added comics.

From the dashboard, the user can click any sidebar link to navigate to that section. The sidebar highlights the current page. The site uses Next.js App Router, so navigation to other pages is fast and preserves layout components like the header and sidebar. Breadcrumbs in the header reflect the current path when the user drills deeper into features.

## Detailed Feature Flows and Page Transitions

In the Comics section, the main content turns into a table view with columns for title, type, status, platform, and actions. Above the table, a search input and filter controls allow users to refine the list by text, genre, or status. Typing in the search box triggers a debounced request to the `/api/comics` endpoint, which returns paginated results. Users can also click “Add New Comic,” which opens a full-screen form. The create form uses react-hook-form and Zod for validation, so any missing fields or invalid URLs produce inline error messages. After filling in title, type, status, platform, genres, and an optional cover image URL, submitting calls the POST `/api/comics` route. On success, a toast notification appears, and the app returns to the updated table showing the new comic.

Clicking the edit icon on a comic row navigates to an edit page with the same form pre-populated with existing values. Submitting an update sends a PATCH request, then shows a confirmation toast before redirecting back to the table. Deleting a comic triggers a confirmation dialog. If the user confirms, the app calls DELETE `/api/comics/:id`, marking the record’s `deletedAt` timestamp. A toast confirms the move to the recycle bin.

The Master Data section is laid out as tabs for Types, Statuses, Genres, and Platforms. Each tab shows its own data table and an “Add” button. For Types, Statuses, and Genres, only administrators or custom entries can be modified; default entries are locked and show a disabled edit or delete icon. Platform entries behave the same but members can add custom platforms. Adding or editing in this section uses forms similar to the Comics form, calling `/api/enums/:category` endpoints for create, update, and delete operations. After any change, the page reloads the tab’s data and shows a toast message.

When users click Recycle Bin, they see a list of all soft-deleted comics and any custom master data entries they have removed. Each row has restore and permanent delete actions. Restoring calls PATCH `/api/comics/:id/restore` or the equivalent for enums, which clears the `deletedAt` flag and returns the item to its original section. Permanently deleting sends DELETE `/api/comics/:id/permanent` for comics or `/api/enums/:category/:id/permanent` for master data. Confirmation dialogs guard against accidental loss, and toasts follow each operation.

The Activity Log page lists recent actions like comic additions, edits, deletions, and master data changes. The list is paginated and can be filtered by date or action type. Clicking any log entry expands a detail view in a panel below, showing who performed the action and the data before and after the change.

A JSON export feature appears in both the Comics and Master Data pages as a button labeled “Export JSON.” Clicking it triggers a GET `/api/export?scope=comics` call, which streams a JSON file download containing the requested scope of the user’s data.

## Settings and Account Management

The Settings page displays the user’s profile information in a form that allows updates to their display name and email. Changing email requires entering the current password for verification. Below the profile section, toggles let users switch between light and dark theme modes. The chosen theme is saved to the database via PUT `/api/users/:id/theme` and applied immediately across the app. Further down, a separate Change Password form asks for the current password, a new password, and confirmation. Submission calls PUT `/api/users/:id/password` and returns an error message if the current password is incorrect or the new password fails strength checks. Upon success, a toast confirms the update.

At the bottom of the Settings page, a link labeled “Back to Dashboard” returns the user to their main dashboard view, preserving scroll position and chart state.

## Error States and Alternate Paths

If a user enters invalid credentials on the login page, an inline message explains the issue without clearing the input fields. On forms throughout the app, Zod validation errors show next to each field, guiding the user to correct mistakes. Network errors during API calls display a full-width red banner at the top of the page and a toast saying "Network error, please try again." If the JWT has expired or is missing, the middleware automatically redirects the user to the login page, explaining that their session has expired.

Attempting to access a protected route without proper authorization, such as a locked master data tab, results in a redirect back to the dashboard with an explanatory toast. When the application cannot find a requested resource, for example an invalid comic ID, a friendly 404 page appears with a link back to the Comics list. In cases of server errors on API routes, the user sees a 500 error page with an option to retry the operation or contact support.

## Conclusion and Overall App Journey

A user’s journey begins on the landing page, where they choose to sign up or log in with secure JWT-based authentication. Upon entering the app, the dashboard provides a clear snapshot of their comic collection through charts and KPIs. From there, the user navigates via the sidebar to perform detailed work: adding or editing comics, managing master data, viewing deleted items in the recycle bin, or reviewing the activity log. The Settings page offers personal profile tweaks, theme control, and password changes. The application gracefully handles errors, expired sessions, and missing data, always guiding the user back to a valid path. Over time, users rely on the JSON export feature for backups and trust the seamless sign-in, sign-out, and password recovery flows to keep their data safe and accessible.
